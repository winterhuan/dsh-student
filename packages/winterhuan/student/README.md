# @winterhuan/dsh-student

English | [中文](README.zh.md)

## Summary

Guide a primary-school learner through Chinese, mathematics and English in the current DSH conversation, with Learning desk shortcuts or `/study`. Keep original answers, help, feedback and later practice across conversations. Parents confirm setup, school progress and photographed work in chat; optional manual forms provide another way to save. There is no time limit. The package supplies selected grade-two first-term Chinese and mathematics pages, grade-one/two knowledge maps and validated reference questions; foundation materials do not establish school alignment.

## Use this package

Install the prebuilt release through the [plugin market](https://winterhuan.github.io/dsh-creative/index.json), or use this pinned Git source with DSH `0.2.2-rc.5`:

```sh
dsh plugin --profile market add 'git+https://github.com/winterhuan/dsh-student.git#v0.2.7&path:/packages/winterhuan/student'
```

Replace `market` with the name of your existing DSH profile.

Open the learner's workspace in the left sidebar and select or create a conversation using **智能学习** (Smart learning). **Learning desk** opens automatically beside the native DSH tutor, with direct entries for Today, Knowledge and progress, Practice and marking, Lesson history, and Learning profile; it can also be reopened from the right sidebar. DSH owns workspace and conversation selection. Each workspace retains one learner's term records, shared across its conversations, and drafts survive closing the sidebar or changing conversations. A workspace without records offers native-chat setup. Legacy records remain browsable and printable; before saving new learning data, ask the tutor to check migration and have the parent confirm it.

Domain Skills and tools remain scoped to Smart learning. Existing conversations keep their mode; Session state and project files are not migrated.

Install the built package into a DSH `0.2.2-rc.5` profile, open a dedicated learning workspace and invoke `/study`.

```sh
dsh plugin --profile student add ./packages/winterhuan/student
```

The profile must already provide Skills, tools, a Session filesystem and sandbox policy. A web profile also supplies chat, image attachments and the Learning desk sidebar. The bundle adds the `student` Host row and the `preset-student` mode row and does not install any creative package. Restart the profile after installing or rebuilding.

DSH `0.2.2-rc.5` Headless does not select the Web preset roster. For a non-Web profile, disable `preset-student` and load the installed Student Agent entry before creating an Agent, using this profile patch:

```yaml
- id: preset-student
  disabled: true
- insert:
    - id: student-headless-capabilities
      name: '@winterhuan/dsh-student/agent'
```

The profile must provide the same native tools and filesystem services. Installation already enables the existing `fs-observation-policy` row; keep one instance. Loading the Student entry after `agent/created` cannot capture ordinary input ownership for that Agent. Restart the profile, create a new Agent, then invoke `/study`.

### Open an interactive lesson

The working-tree unit-course implementation follows directory → complete interactive lesson for the current section → later review mini lessons. Lesson history organizes the actual edition, text, directory and within-unit school position. Generate only the explicitly selected section and start later sections on demand. Generate a unit synthesis after school completion or explicit test preparation. Save a six-stage teaching plan before `openmaic_generate`; review the actual content, question allowance and answer criteria before opening the classroom.

Buttons show short intentions and preserve verbatim answers; execution metadata stays in the native message source. Progress checks query the original job without inference; unknown submission outcomes retain that identity without automatic resubmission. Reusable mini lessons retain HTML and a content fingerprint for direct isolated display; external scripts and network requests are outside that preview. Viewing, generation success and activity completion grant no mastery. These changes do not replace the daily remote installation before isolated real-service and performance acceptance is complete.

Student includes the fixed official OpenMAIC 0.4.0 bundle: four tools and four DSH skills for complete classrooms, independent simulation/game/code widgets, slides and teaching cards. The Host uses the official service by default, renews protected account authorization inside 24 hours of expiry, verifies the same learner, and retries safe reads after a confirmed 401 once. Generation submissions are never automatically replayed after a refusal, redirect or unknown result. A generation returns structured job identity promptly; continuing the same activity polls its original job after restart. The agent authors every learning file and validates it with the read-only CLI. The [24-method source inventory](knowledge/skills/study/openmaic/README.md) retains official sources and distinguishes reusable teaching guidance from website-only workflows; bodies and references load on demand.

The Host bounds each network request, including its body, to `requestTimeoutMs` (30 seconds by default), and each authorization/generation operation to `operationTimeoutMs` (120 seconds). Responses stop at 8 MiB before JSON parsing. Canceling local waiting preserves an accepted job and does not cancel it on the service. Poll addresses and every read redirect must remain on the configured origin; raw errors and response headers never enter tool receipts.

A dedicated installed-Chrome window follows official sign-in and verifies the account before playing a classroom. Challenges retain that same window for parent sign-in; arbitrary system browsers keep their own login state.

Installing Student enables the profile's existing DSH Credentials provider, including in headless. Its configured store is preserved, explicit user patches retain precedence, and saved references take precedence over environment fallbacks. Student's `openmaic` Host configuration defaults to the credential references `OPEN_MAIC_USER`, `OPEN_MAIC_PASSWORD` and `OPEN_MAIC_ACCESS_CODE`; resolve their values through the protected provider rather than writing them in plugin configuration. Account authorization and job recovery use private provider grant records. `browserProfileRoot` optionally selects a private persistent Chrome directory; the default is `DSH_HOME/student-openmaic-browser` (or `~/.dsh/student-openmaic-browser`). Browser open/continue checks expiry, and Host disposal closes its owned Chrome context; restarting reuses that profile. The prebuilt package bundles the fixed official Host and its npm dependencies, publishes the unchanged official browser bundle through a client-only Loader entry, and keeps tools and skills scoped to Student. Installation needs no build or installer policy changes; generated `lib/openmaic/source.json` records the fixed source and dependency lock.

Student enables the profile's existing `fs-observation-policy` before native file tools in Web and Headless. Native overwrites require a read and reject changed versions or concurrent creation; re-read and merge before retrying. Observations do not survive Session restart. Shell commands, external editors and multi-file migrations remain outside this single-file guard, so keep backups and report conflicts or partial completion.

DSH reads the project `.env` from the directory where it is launched, with `$DSH_HOME/.env` as a fallback; changing profiles does not load another working directory’s `.env`. For isolated verification, launch from the project directory containing the credentials or save the references through DSH credential settings. Restart the Host after editing `.env`. Keep passwords out of chats and course files.

### Choose a learning activity

Smart learning chooses a main activity and any needed short review from the current records. Children can change content or ask their own question in native chat. Parents can initiate a check-in from Knowledge and progress or a review from Practice and marking. These activity types remain available through the tutor; they are separate from the daily arrangement.

| Activity | When to use it | Prerequisite |
|---|---|---|
| Sync | Practise the confirmed school unit, or labelled authored examples after an explicit foundational-lesson choice | Parent-confirmed learner profile |
| Due review | Recall a previously confirmed mistake or try a related variation | Confirmed mistakes due for review in the selected subject |
| Check-in | Sample a few short questions from the knowledge map to find what is known and what needs work, at light, standard or deep intensity | Learner profile; suggested every 14 days per subject, repeatable any time |
| Explore | Investigate a child's question through a prediction, observation and explanation | Learner profile; explain the question in chat |

Before the first activity, confirm the learner profile in Learning profile; existing school progress supplies the default learning range, and parents may optionally adjust it. A parent can correct and confirm a tutor-proposed concept’s definition, example and source; the tutor then creates learning goals and evidenced prerequisite, part, contrast, explanation or causal relations. Old mistakes retain their original `topic` until checked and linked to a goal. Changing activities preserves pending questions and answers. Submit an answer and wait for feedback; Pause retains the resumption point, while Finish for today records unfinished work in the summary.

The mistake book prints a daily mini sheet, practice sheets and review sheets. A daily mini sheet has 4–6 questions from the subject routine (characters or words, a sentence or oral arithmetic, and one variant of a recurring error cause). A practice sheet covers the current school unit, mixes question types, and leaves space to write. For a review sheet the system picks the mistakes: up to 8 due today or tomorrow, lowest review stage first, one variant each, skipping mistakes already printed on a sheet that has not been marked. A sheet renders as a web page: the parent previews the whole sheet in the workbench and prints through the browser print dialog, choosing a printer or "Save as PDF"; Windows prints the same way. The sheet can draw bar models, Chinese money, tens-and-ones dot diagrams and counters, a hundred chart (including a nine-cell window), number lines, clock faces at any five-minute step, counting sticks, column-arithmetic grids, shape comparisons, plane and solid figure rows, overlap circles (sum circles and set diagrams), number splits, pattern strips, number walls, grids, dot arrays, centimetre rulers, direction crosses, balances, tianzige squares and four-line letter bands, plus a sketch fallback for anything else, each with one line, three lines or a box to answer in; the on-screen task figures and the printed figures are the same set. The sheet contains questions, figures and answer space; answers and evidence remain in the learning record.

After the child finishes, the parent expands the sheet in the mistake book, marks each question right, partly right or wrong against the answer key, optionally types what the child wrote and tags the error cause, and saves; a photo of the sheet can also go to the tutor, who saves each question as a transcription draft for the parent to confirm through chat or the optional manual form. A wrong or partly right answer on a practice sheet becomes a mistake on that question's goal, and correcting the mark to right removes it. Each review question climbs a numeric, then context, then reasoning ladder and keeps the mistake's error cause. Review questions count by day: an independent correct answer on any day, earlier than the due day included, moves the mistake to the next stage and the next review counts from that day, while a wrong or partly right answer only makes it due again the next day (a repeated wrong waits two days) without lowering the stage. A sheet that will not be used can be discarded so its mistakes can be printed again. Paper results need no active timer and earn no stars.

If DSH's SenseVoice input is enabled, the learner can dictate an answer in chat. The transcript enters the draft for review before sending; the tutor then saves the original text against the current task. A transcript cannot assess reading or English pronunciation. The desk does not add another recorder.

### Confirm the learner and materials

Each workspace holds one learner’s term in format 2 official files. Native chat is the default setup and management entry; a parent confirms nickname, region, grade, term, school year, school system, interests and an optional course note. Unknown years remain unknown until confirmed. Profile edits preserve historical learning context; confirmed courses and school progress share one settings write. Foundation practice can begin after basic setup while school alignment is pending. Archive retains original term identities and sources; a new term uses a new identity. Legacy sources remain readable and require explicit migration before new official-file work.

Confirm each subject's book title, publisher, edition, cover/copyright evidence and current unit separately. After the textbook is confirmed, choose the map unit the class has reached in Learning profile settings: new goals and check-ins stay in that unit and the units already taught. Keep-up teaches the current unit, catch-up fills earlier gaps first, a review week adds no new goal, and preview covers at most the next unit. The frontier moves only after confirmation. School study requires an identified edition, matching curriculum scope and a recorded parent confirmation. Unconfirmed courses can use clearly labelled foundation practice. Materials retain separate identities when an edition changes; earlier attempts keep their original material reference. Official entry points and source rules live in [materials](knowledge/skills/study/references/materials.md).

### Use default textbooks

For grade two, first term, `/study` uses the bundled People's Education Press Chinese or Beijing Normal University Press mathematics textbook when the user supplies no textbook for that subject. User-provided books and pages take priority. You do not need to upload these two books again: complete the learner profile and choose Foundations, or ask in chat to learn multiplication with the default mathematics textbook. Without a selected topic, the tutor offers a short choice from the first unit. Defaults do not establish the school's edition or fill in school progress; English, other grades and other terms have no default textbook.

See [default textbooks](knowledge/skills/study/references/default-textbooks.md) for contents, edition evidence and reading rules. DSH's `read_image` reads selected pages and requires an image-capable model. Extracted text supports lookup only; it cannot directly establish pinyin, diagrams or column calculations for grading. Without image support, use user-provided or previously verified prompts, or clearly labelled generated foundation exercises.

### Use the knowledge map and weak points

The package ships twelve knowledge maps for Chinese, mathematics and English across both terms of grades one and two, organized from the first-stage requirements of the 2022 curriculum standards. Chinese and English for both terms of grade one and the first term of grade two list the units and lessons from the parent-confirmed textbook contents. Mathematics for those three books follows the 2024 Shanghai five-four textbook contents. Grade two, second term of all three subjects keeps the earlier framework. They are a learning framework, not the school textbook or the teacher's progress. Map learning goals need no parent confirmation for questions, answers, mistake classification or worksheets; the tutor reads each knowledge point's definition, example and checkable facts with `study_status kind=curriculum` before asking, and records the goal on every question. Every knowledge point on the twelve maps has checkable facts, and a question may not go beyond them. Chinese, grade two, first term, is taken from the bundled People's Education Press pages. In Chinese, grade one, both terms, a knowledge point whose 2024 unified textbook page was read clearly now states the lesson lines, characters and stroke names; lessons 1 a o e and 2 i u ü keep their earlier facts. Chinese, grade two, second term, still states what that lesson can be checked against. English, grade two, first term, Units 1 to 4 follow a parent reading sheet. Units 5 to 10 of that book, grade one first term Units 1 to 6 and Units 8 to 10, and grade one second term Units 1 to 10 use sentences read from 2024 Shanghai five-four excerpts. Grade one first term Unit 7 changes only the sentences that match. Starter, both appendices and grade two, second term, still state what the topic words mean. For mathematics, grade one both terms and grade two first term, a knowledge point whose lesson page or plan was read, and whose concept matches, now states the method, rhyme or shape feature on that page. A point without a matching page keeps its earlier facts. Mathematics, grade two, second term, is unchanged in this pass. A later page or paper can replace a fact when it is the same concept. Publisher and volume may differ. Paper questions corroborate the course, and a new question is written again rather than copied.

Recommendations, the knowledge map, weak points and Learning profile use the same capability progress for the confirmed range. Progress retains actual independent response dates, incorrect or helped attempts, due reviews and pending source verification. A narrower learned range does not grant mastery of an expanded range. Unmapped historical records remain visible as Needs association. Completing today’s arrangement is separate from long-term mastery; it may finish with consolidation still needed. These states describe the available evidence and do not replace school assessment. See [daily planning](knowledge/skills/study/references/daily-planning.md) for selection and closure, and [knowledge map](knowledge/skills/study/references/knowledge-map.md) for map coverage and queries.

The optional parent-initiated check-in is a short, recurring probe, separate from daily task size: for each subject it samples untouched goals across units, then goals not practised lately and mastered goals older than 35 days, and suggests another round 14 days after the last one; it can be repeated any time. Three intensities are available: light (3 choice questions), standard (6, the default) and deep (up to 12 with one reasoning task per unit and re-checks of goals in progress); the desk recommends one from the number of untouched goals. Built-in diagnose exercises from the exercise bank can seed each sample. The confirmed school frontier is the default sampling range, not a limit: a check-in can also run in another grade and term, in selected units, or against a picked set of goals by passing that scope when the block starts, and answers are only checked against the chosen scope. Each sampled goal gets one short question and every answer must carry the learning goal; a goal never answered independently is marked as needing work after a single wrong answer, and today's plan turns to targeted practice. A check-in has no score or ranking and no time cutoff.

### Learn and review

The tutor starts one learning block, asks a short question, waits for the learner and records the actual response and help received. There is no block, break or daily minute limit; a child may stop when tired without penalty or catch-up. Elapsed time is quiet clock time including waiting, and stop stores the actual elapsed time. Calendar days use Shanghai time. No background alarm or screen lock is installed. Record matching, choice normalisation and diagnose intensity remain in the [soft-time decision](https://github.com/winterhuan/dsh-creative/blob/feat%2Fstudent-native-chat/.agents/notes/implemented/bug-fix/2026-10-18-student-soft-time.md); removal of durations is in the [overhaul decision](https://github.com/winterhuan/dsh-creative/blob/feat%2Fstudent-native-chat/.agents/notes/implemented/feature/2026-10-30-student-overhaul.md).

Actual recorded work earns at most one participation star per day; a learner's reflection can earn one additional star. Idle time, more questions, longer sessions and consecutive days earn no extra stars. The progress report shows evidence and topics, not rankings or exam scores.

For a photo mistake, the tutor reads the image through DSH, saves the transcription with uncertainties and asks the user to confirm the corrected prompt and answer evidence. Every new mistake remains pending until confirmation. The first review is due on the day after confirmation; an independent correct answer on any day, before the due day included, extends the interval along 1, 7, 16 and 35 days, at most one stage per day. Helped or incorrect answers only make it due again the next day without lowering the stage. Review stages are recomputed from all recorded answers, so a corrected mark updates them. Three different days of independent answers are reported as evidence, not permanent mastery. Parents may also enter, edit or delete confirmed mistakes through chat and save items into the workspace exercise bank for later variants.

Ask `/study` to review progress, continue due mistakes or explore a child's question. Exploration uses a small prediction, observation and explanation cycle around an inquiry the child types. Optional daily reminders use DSH's available reminder tools only after a parent specifies the schedule; this package creates none automatically.

## Understand the implementation

Ownership and trust boundaries: [Student subsystem](https://github.com/winterhuan/dsh-creative/blob/codex%2Fstudent-openmaic-loop/docs/subsystems/student.md). From the repository root, build with `pnpm --filter @winterhuan/dsh-student build` and test with `pnpm --filter @winterhuan/dsh-student test`.

The Host entry owns validated workspace reads, typed manual saves and configuration. The `./agent` export registers domain Skills and tools inside the `student` preset and inherited native child compositions. The preset supplies a task-specific persona and explicit native tools; it does not change the default mode. Learning uses filesystem, search, web, questions, presentation and platform-specific shell tools without delegation or creative production workflows.

The [profile patch](cordis.patch.yml) loads the [host plugin](src/index.ts). The [knowledge-map loader](src/curriculum.ts) reads and validates the twelve maps in `knowledge/curriculum/` and the exercise bank in `knowledge/curriculum/exercises/`; state files keep goal references only. Demonstrations stay in teaching content. Published worksheets freeze each question’s content, goal and historical context; source mistake edits or deletion leave them usable, and replacing content requires a new identity. Confirmed workbook photos retain their original responses and outcomes, without treating receipt time as an answer date. The packaged CLI and on-demand authoring schemas use those source definitions. DSH's normal tool log records calls and results.

The [official-file API](src/files/index.ts), exported as `./files`, shares strict schemas and business validation between application reads, typed manual saves and read-only Node consumers. Format 2 stores term settings in `.study/settings.json`, one block in `.study/blocks/<blockId>.json`, one worksheet in `.study/worksheets/<worksheetId>.json`, one daily arrangement in `.study/plans/YYYY-MM-DD.json`, and bounded remaining collections in `.study/collections.json`; OpenMAIC keeps its independently validated `.study/openmaic-lessons.json`. Reads check directory membership and actual file versions with at most three attempts. Validated file, backup and query caches belong to the application Host and clear at its disposal; read-only adapters retain their own caches. Evidence and dashboard caches belong to their projected state. An invalid entity pauses its related saves. Settings and materials return explicit partial reads when unrelated files are invalid; incomplete evidence blocks summary projections. The application retains up to three observed valid versions per entity in `.study/backups/`, within 128 backups and 32 MiB of source bytes. One Host owner serializes complete backup retention operations for the same settings-file target; custom file adapters without that owner guarantee only sequential retention. Backup discovery, read, pruning and write failures are reported separately and leave valid business reads and saves usable. Restore descriptions require an explicit choice and preservation of the invalid original. The desk restores drafts before rendering through its registration-declared store, and components call the Host through plain callbacks. Manual saves check the term identity, edited-field baseline and current file versions. Profile saves merge selected edited fields with untouched current values; course and school progress share one settings write. Original-byte-verified v1 migration and archive descriptions expose each output and missing source fact without writing or repairing business files. Official files are limited to 8 MiB each and 32 MiB per active term, with at most 5,000 blocks, 500 worksheets and 128 archived term directories. Plans additionally allow at most 1,000 files and 1 MiB per file within the same total budget. Daily reads include today, recent actual learning days, the resumed owner and direct original references; historical queries select a specific day. Invalid plan metadata preserves original learning records and pauses affected progression. Plans save stable tasks, reasons, ending conditions and explicit choices; answers and mastery remain in their original evidence. Reads never save a preview, and midnight never starts a new activity. Legacy `.study/state.json` remains readable without changing its bytes; grading times, receipt times and default independence do not become verified learning evidence. A verified migration backup identifies required outputs; missing files keep the workspace migration-incomplete and withhold current facts until completion.

### Rehearse recovery

After building, run the real native-tool recovery suite with an installed DSH `0.2.2-rc.5` executable and an evidence directory outside the repository:

```sh
DSH_BIN=/absolute/path/to/dsh STUDENT_EVIDENCE_DIR=/path/to/evidence pnpm run test:recovery
```

The suite uses isolated temporary Home, Agents and Documents directories, then awaits subprocess cleanup. It covers preserved synthetic v1 sources, interrupted migration and changed-source refusal, bounded observed backups, explicit restore, partial archive, new-term refusal and restart through actual native write/edit, the built CLI and independent consumers. This does not run the old plugin in a separate recovery workspace or establish browser, fixed-Git, real tutoring, OCR, classroom or physical printer acceptance.

The [official feedback reader](src/openmaic/feedback.ts) freezes question snapshots before playback and rereads the original authorized learner sessions and records. The agent saves the returned binding, questions, immutable submissions and official review history in the original learning files, runs the built read-only CLI, and advances its lesson checkpoint only after independent Student consumption accepts the saved import. Equivalent numeric choices keep both the original official and effective grades. Nonnumeric alternatives remain pending until an explicit parent criterion correction matches an independently consumed native input and the original response and snapshot; the correction retains the original official history and grants no answer date or independence. Reviewed-only, conflicting and ambiguous cross-session records remain complete original events in the owning block’s pendingOpenmaic array. Complete saved pending facts may acknowledge a read without granting mastery; incomplete or oversized reads keep the previous checkpoint. Unknown dates and help remain unknown. A model-written source or confirmation marker never authenticates evidence. See the [feedback workflow](knowledge/skills/study/references/openmaic-feedback.md).

After building, run `node packages/winterhuan/student/tests/openmaic-feedback-native.e2e.mjs` for deterministic HTTP-source/native-authoring/CLI/independent-read/restart acceptance. Set `DSH_BIN` for the installed executable and `STUDENT_EVIDENCE_DIR` for evidence outside the repository. An optional `STUDENT_OPENMAIC_ONLINE_DIR` holds private original job/auth/capture metadata for online source acceptance; its evidence directory must remain private. This mode preserves existing generation ownership and verifies actual source imports; full native classroom generation is a separate acceptance.

### Validate native file edits

Build this repository, then run the same executable shipped in the package:

```sh
node packages/winterhuan/student/lib/cli.js --help
node packages/winterhuan/student/lib/cli.js schema term-settings
node packages/winterhuan/student/lib/cli.js example figure
node packages/winterhuan/student/lib/cli.js validate --workspace /path/to/workspace
```

For an installed package, use `<study Skill Base directory>/../../../lib/cli.js`; the `./cli` export and `study-validate` bin identify the same executable. DSH Git installation does not promise a global PATH command. Validation reads official files and the full independent lesson log, preserves bytes/revisions, and creates no backups or repairs. Exit 0 identifies observed kinds, identities and versions; nonzero JSON names the path, field, rule and correction. Validation output is at most 32 KiB with explicit omissions. ### Study guidance and records

#### What the model sees

The Student preset adds `study_status`, `openmaic_feedback` and the four official OpenMAIC tools, plus the study skill and four official DSH skills. The [prompt snapshot](../../../tests/fixtures/student-persona.txt) records its prefix; Standard and sibling modes omit these tools and skills. Official authoring contracts and the selected method resources load only when needed. Host account credentials and browser authorization remain outside model parameters, tool receipts and learning files. Agents author all learning changes with native file tools, run the packaged read-only CLI, and distinguish admitted messages, saved answers and valid assessments.

#### Token effect

Skill bodies and references load on demand. Two read-only Student tool schemas are advertised when enabled; native tools also contribute to each request. Collection queries return 20 records with a next offset. Textbooks are not loaded as a whole. Two isolated DSH 0.2.2-rc.5 first requests with the same empty workspace, input and Web-like preset composition measured a fixed-density estimate of 8,765 tokens for the baseline package and 10,808 for the official composition: +2,043 (+23.3%), including messages and tool definitions. The separate Headless entry composes capabilities before Agent creation; native tests cover its actual invocation path. The 24 official method bodies remained deferred. These requests made no paid model calls or academic writes; the estimate does not measure provider billing, total lesson cost, teaching quality or KV Cache performance.

#### KV Cache effect

The plugin uses ordinary DSH Skill and tool history. It does not rewrite previous messages or create another model session.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- Mathematics units and knowledge points for both terms of grade one and the first term of grade two follow the 2024 Shanghai five-four textbook contents, but they are not a page-by-page copy. Chinese and English for those three books list the lessons and sections from the parent-confirmed contents, and are not a page-by-page copy either. Grade two, second term of all three subjects keeps the earlier framework and may differ from the school's book. Mastery counts only records that carry a learning goal, so older answers without one stay outside weak-point analysis. A check-in probes at most six goals per round, sampled across units but not a complete assessment; the model writes the probe questions, and where checkable facts exist the answer stays inside them, so parents should still watch their quality.
- The plugin does not authenticate a parent's identity, verify attention, guarantee AI answers or supply a complete Shanghai curriculum. A confirmation records a user statement; source classification alone does not prove correctness. Actual textbooks, school progress and disputed answers still need human checks.
- Image intake depends on a vision-capable DSH model and readable attachments. This package has no OCR service, textbook downloader or automatic reminders. Image paths reference the supplied attachment; the package does not copy image bytes into its state file. Voice input needs the separately enabled DSH bundle, and transcription does not verify pronunciation.
- Printing goes through the browser print dialog with a physical printer or "Save as PDF". The parent checks actual paper output and the browser's print status; this package keeps no print-queue receipt.
- There is no time limit on recorded learning actions; the plugin still cannot lock the operating system or arbitrary chat. Application saves and native write/edit tools check observed versions; shell and external writes and multi-file transactions remain outside that single-file guard. Observed backups cannot recover overwritten history that was never read, and migration and archive publish each file separately.
- State is local, but excerpts and images used in tutoring reach the configured model provider. The plugin is not an offline or encrypted learning vault. Native tool and filesystem tests do not establish real-model transcription accuracy or educational effectiveness.

- Unit courses independently review questions before generation, then compare original questions and review all generated scenes. Grammar errors, false facts, ambiguity, uncertainty and incomplete review block playback. Protected receipts bind the original job and material fingerprints; reopening invokes no model. The official generator may rewrite questions, which requires rejection and an explicit replacement. This flow has not passed the complete real-learning and performance release gates.
- Complete classrooms use an external OpenMAIC service. Browser playback requires installed Google Chrome; login challenges require a parent in the same dedicated window. The lesson log retains historical records across terms. Website-only stage editing, import and constraint execution are inventoried but not supplied by the four DSH tools.
- Transcriptions, review variants and daily mini sheets are model-written. A photographed sheet first becomes transcription drafts; the parent confirms them through chat or the optional manual form before results and error causes enter the record, and printed practice remains the main learning surface.
